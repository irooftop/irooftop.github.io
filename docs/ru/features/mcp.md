# Инструменты MCP

**Настройки → MCP-серверы** принимает обычный JSON `mcpServers`:

```json
{
  "giphy":  { "command": "npx", "args": ["-y", "mcp-server-giphy"], "env": { "GIPHY_API_KEY": "…" } },
  "remote": { "url": "https://example.com/mcp", "headers": { "Authorization": "Bearer …" } },
  "legacy": { "url": "https://old.example.com/sse", "type": "sse" }
}
```

* Инструменты попадают к модели как `mcp_<сервер>_<инструмент>`. GIF, найденный через Giphy, отправляется с помощью `send_gif {url}`.
* В `env`, `headers`, `args`, `command` и `url` можно использовать `${ИМЯ}` из окружения или `.env`, чтобы секреты оставались вне `settings.json`.
* Серверы stdio работают в собственном каталоге, `data/mcp/<сервер>/`.
* **Переподключить MCP** в Настройках перезапускает их; статус показывает протокол и инструменты каждого сервера.

## Версии протокола

| Версия | Транспорт | |
|---|---|---|
| `2026-07-28` | Streamable HTTP, без состояния | сначала проверяется через `server/discover` |
| `2025-11-25`, `2025-06-18`, `2025-03-26` | Streamable HTTP или stdio | рукопожатие `initialize`, сессии |
| `2024-11-05` | HTTP+SSE (устаревший) | последний запасной вариант |

```
 server/discover (2026-07-28)
   ├─ ok ─────────────────────────────▶ без состояния
   ├─ -32022 версия не поддерживается ─▶ сменить версию
   └─ иначе ─▶ initialize ─┬──▶ сессия (повторный initialize при 404)
                           └──▶ устаревший HTTP+SSE
```

Запросы elicitation и sampling (`input_required`) сообщаются модели как ошибки.
