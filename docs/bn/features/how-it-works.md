# এটি কীভাবে কাজ করে

<div class="wide">

![iRoof.top কীভাবে কাজ করে](/how-it-works.svg)

</div>

প্রতিটি এক্সপোর্ট একই স্বাভাবিকীকৃত বার্তায় পরিণত হয়। তারপর পার্সোনার প্রতিটি কাজ মডেলকে একটি **টুল কল** হিসেবে পুনরায় চালানো হয়, যাতে মডেল শেখে ব্যক্তিটি *কীভাবে* আচরণ করে, শুধু কী লেখে তা নয়, এবং একইভাবে উত্তর দেয়।

## কাজ টুল কল হিসেবে

| পার্সোনা যা করেছে | ইতিহাসে ও লাইভ উত্তরে টুল কল |
|---|---|
| টেক্সট বাবল, হয়তো একটি উত্তর বা আংশিক উদ্ধৃতি | `send_message {text, reply_to?, quote?}` |
| স্টিকার | `send_sticker {sticker_id, reply_to?}` |
| লাইব্রেরি থেকে GIF, বা একটি MCP টুলের URL | `send_gif {gif_id \| url, caption?}` |
| ছবি, ভিডিও, ভয়েস, অডিও, ফাইল | `send_media {media_id, caption?}` |
| ফরওয়ার্ড করা পোস্ট | `forward_message {message_id}` |
| প্রতিক্রিয়া | `react {message_id, emoji}` |
| *(পুরোনো ইতিহাস মনে করা)* | `search_history {query}` |

একটি পালায় একাধিক কল একাধিক বাবল হয়। অন্য পক্ষের বার্তাগুলো সংক্ষিপ্ত লাইনে পরিণত হয়, যেগুলোকে আইডি নির্দেশ করে:

```text
#52108 19:08 ↩ #52107-এর উত্তর (আপনি: "দাদির লাজানিয়া 🍝"): আপনি জীবনে একবারও লাজানিয়া বানাননি।
<sticker stk_156dbb381a>: একটি বিড়াল শেফের টুপি পরে পাত্র নাড়ছে
#52107-এ ("দাদির লাজানিয়া 🍝") 😂 প্রতিক্রিয়া দিয়েছে
```

## সিস্টেম প্রম্পট

| অংশ | |
|---|---|
| কে হতে হবে | পার্সোনার জ্ঞান ও স্টাইল অনুমান করা, এবং সে যা জানত তার চেয়ে বেশি কখনো না জানা |
| স্টাইল প্রোফাইল | *পুরো* এক্সপোর্ট থেকে: বার্তার দৈর্ঘ্য, বড় হাতের অক্ষর, বিরামচিহ্ন, ইমোজি ও স্টিকারের ব্যবহার, উত্তর ও প্রতিক্রিয়ার অভ্যাস, পালায় বাবলের সংখ্যা, শব্দশ নমুনা |
| লাইব্রেরি | স্টিকার, GIF ও মিডিয়া, এবং সেগুলো কীভাবে ব্যবহৃত হয়েছে |
| নোট | আপনি ব্যক্তিটি সম্পর্কে যা লিখেছেন |

একটি চ্যাটের জন্য প্রম্পট **স্থির**: কোনো ঘড়ি নেই, কোনো কাউন্টার নেই। মডেল `— দিন —` বিভাজক ও `HH:MM` টাইমস্ট্যাম্প থেকে সময় পড়ে, এবং প্রতিটি অনুরোধ পরবর্তী অনুরোধের বাইট-বাই-বাইট একই উপসর্গ, তাই প্রদানকারীদের প্রম্পট ক্যাশ সবসময় কাজে লাগে।

## দীর্ঘ চ্যাট {#long-chats}

```
 ইতিহাস বাজেট ───────────────────────────────────────────▶
 ┌──────────────────────┬────────────────────────────────────────┐
 │ স্মৃতি (≤ ৩৫০ শব্দ) │ সাম্প্রতিক পালা, বাজেটের ৬০% পর্যন্ত ছাঁটা│
 └──────────────────────┴────────────────────────────────────────┘
   সম্পর্ক, তথ্য,         ছাঁটাইয়ের বিন্দু দীর্ঘ সময় একই জায়গায়
   বিষয়, রসিকতা        থাকে, তাই ক্যাশ করা উপসর্গও থাকে
```

পুনরায় চালানো ইতিহাস বাজেট ছাড়ালে, পরের উত্তর আগে সবচেয়ে পুরোনো পালা (এবং আগের স্মৃতি) একটি ছোট সারাংশে গুটিয়ে নেয়। ইমপোর্টে বা চ্যাট খুললে কিছুই খরচ হয় না। স্টাইল প্রোফাইল এখনো পুরো এক্সপোর্ট থেকে আসে, এবং `search_history` প্রতিটি পুরোনো বার্তায় পৌঁছায়। টোকেনের `usage` (প্রম্পট, ক্যাশ, সম্পূর্ণতা) `{ }`-এ দেখানো হয়।

## মিডিয়া লাইব্রেরি

চ্যাট মডেল টেক্সট পড়ে, তাই একটি স্টিকার বর্ণনা না হওয়া পর্যন্ত শুধু `<sticker stk_…>`। **AI দিয়ে বর্ণনা করুন** অনুপস্থিত আইটেমের ছবিগুলো মিডিয়া মডেলে পাঠায়, যাকে ভিশন সমর্থন করতে হবে।

* GIF, ভিডিও স্টিকার ও ভিডিও **ক্রমানুসারে ৪টি ফ্রেম** হিসেবে যায়, যাতে মডেল গতি দেখতে পায়। এর জন্য [ffmpeg](https://ffmpeg.org) লাগে (`brew install ffmpeg`, `apt install ffmpeg`, `winget install ffmpeg`); নইলে থাম্বনেইল ব্যবহৃত হয়।
* **আবার করুন** একটি আইটেম আবার বর্ণনা করে। যেকোনো বর্ণনা হাতে সম্পাদনা করা যায়।
* বর্ণনাগুলো এক্সপোর্টের, এবং তার সব চ্যাটে কাজে লাগে।

[CLI](../reference/cli) দিয়ে নিজে দেখুন: `rooftop convert <এক্সপোর্ট> --persona "Jonas Weber"`।
