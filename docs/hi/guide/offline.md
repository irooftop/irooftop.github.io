# ऑफ़लाइन और गोपनीयता

iRoof.top आपकी चैट आपके कंप्यूटर पर रखता है। अगर मॉडल भी आपके कंप्यूटर पर चलता है, तो **कुछ भी उसे छोड़ने की ज़रूरत नहीं**।
**ऑफ़लाइन मोड** इसे एक ऐसा नियम बना देता है जिसे ऐप लागू करता है, केवल आदत नहीं।

## स्थानीय रूप से क्या होता है

| चरण | कहाँ चलता है | नेटवर्क |
|---|---|---|
| इम्पोर्ट, पार्सिंग, स्टाइल प्रोफ़ाइल | आपका कंप्यूटर | कोई नहीं |
| स्टोरेज | डेटा फ़ोल्डर में JSON फ़ाइलें और मीडिया | कोई नहीं |
| इतिहास में खोज, लिंक के PIN, मीडिया लाइब्रेरी | आपका कंप्यूटर | कोई नहीं |
| फ़ोटो, स्टिकर, GIF, वीडियो का वर्णन | **मीडिया मॉडल**, केवल जब आप **AI से वर्णन करें** दबाते हैं | हर आइटम के लिए मॉडल एंडपॉइंट पर एक अनुरोध |
| आवाज़ का ट्रांसक्रिप्शन | मीडिया मॉडल, जब आप वॉइस संदेश पर **AI से वर्णन करें** दबाते हैं या एक रिकॉर्ड करते हैं | मॉडल एंडपॉइंट पर एक अनुरोध |
| एक जवाब | **चैट मॉडल**, जब आप संदेश भेजते हैं (या विज़िटर भेजता है) | मॉडल एंडपॉइंट पर अनुरोध |
| लंबे इतिहास का संक्षेपण | चैट मॉडल, जवाब के हिस्से के रूप में, जब इतिहास बजट से ज़्यादा हो | मॉडल एंडपॉइंट पर एक अतिरिक्त अनुरोध |

इम्पोर्ट कभी मॉडल को नहीं बुलाता। पहली कॉल तब होती है जब आप संदेश भेजते हैं, **वर्णन करें** दबाते हैं, या वॉइस संदेश रिकॉर्ड करते हैं। एक जवाब मॉडल को आपका एक्सपोर्ट किया हुआ इतिहास ([इतिहास बजट](../reference/configuration#settings-only) तक), स्टाइल प्रोफ़ाइल और मीडिया वर्णन भेजता है। इसलिए **मॉडल कहाँ चलता है, यह तय करता है कि आपकी चैट कहाँ जाती है**: क्लाउड एंडपॉइंट उसे पाता है, आपके कंप्यूटर पर चलने वाला मॉडल नहीं।

## केवल ऑफ़लाइन चलाना

1. [Ollama](https://ollama.com) या [LM Studio](https://lmstudio.ai) इंस्टॉल करें, या llama.cpp का `llama-server` चलाएँ।
2. **टूल कॉलिंग को सपोर्ट करने वाला चैट मॉडल** डाउनलोड करें, और अगर आप चाहते हैं कि फ़ोटो और स्टिकर का वर्णन हो, तो एक **विज़न मॉडल**।
3. **सेटिंग्स** में एंडपॉइंट और मॉडल चुनें, फिर **ऑफ़लाइन** चालू करें:

| सर्वर | बेस URL |
|---|---|
| Ollama | `http://localhost:11434/v1` |
| LM Studio | `http://localhost:1234/v1` |
| llama.cpp `llama-server` | `http://localhost:8081/v1` (इसका डिफ़ॉल्ट पोर्ट `8080` iRoof.top का है: `llama-server --port 8081` से शुरू करें) |

4. **टेस्ट** दबाएँ। यह एक छोटा अनुरोध भेजता है और जिस मॉडल और होस्ट ने जवाब दिया, वह दिखाता है। आप नेटवर्क बंद करके भी चैट जारी रख सकते हैं।

**डेस्कटॉप ऐप** सेटिंग्स में कॉन्फ़िगर होता है। यह आपका शेल या `.env` फ़ाइल नहीं पढ़ता ([डेस्कटॉप ऐप](./desktop) देखें), लेकिन जिस एनवायरनमेंट के साथ इसे शुरू किया गया, उसमें `ROOFTOP_OFFLINE` और `OPENAI_*` हों तो उनका सम्मान करता है। एक सर्वर एनवायरनमेंट (और `.env`) पढ़ता है:

::: code-group

```sh [Homebrew / cargo सर्वर]
# --offline, ROOFTOP_OFFLINE=1 के बराबर है
OPENAI_BASE_URL=http://localhost:11434/v1 OPENAI_MODEL=llama3.1 rooftop --offline
```

```sh [Docker]
docker run -p 8080:8080 -v rooftop-data:/data \
  --add-host=host.docker.internal:host-gateway \
  -e ROOFTOP_OFFLINE=1 \
  -e OPENAI_BASE_URL=http://host.docker.internal:11434/v1 -e OPENAI_MODEL=llama3.1 \
  ghcr.io/irooftop/rooftop
```

:::

Docker में `localhost` कंटेनर खुद है, इसलिए `host.docker.internal` का उपयोग करें (`--add-host` विकल्प केवल Linux पर चाहिए)। अगर Ollama कनेक्शन अस्वीकार करता है, तो उसे सभी इंटरफ़ेस पर सुनने दें (`OLLAMA_HOST=0.0.0.0`)।

### ऑफ़लाइन मोड क्या लागू करता है

| | ऑफ़लाइन मोड |
|---|---|
| चैट, इतिहास का सारांश, मीडिया वर्णन, आवाज़ का ट्रांसक्रिप्शन | अस्वीकार, जब तक एंडपॉइंट [स्थानीय](#local-means) न हो |
| HTTP से जुड़े MCP सर्वर | स्थानीय न हों तो अस्वीकार; सेटिंग्स में त्रुटि के रूप में दिखता है |
| इंटरनेट पर साझा करना (`<नाम>.iroof.top`) | बंद: रिले क्लाइंट शुरू नहीं होता और स्विच लॉक रहता है |
| Telegram बॉट, अपना या साझा | शुरू नहीं होता |
| URL से GIF | AI गैर-स्थानीय URL से GIF नहीं भेज सकता |
| Wi‑Fi शेयर लिंक | काम करते हैं |

अस्वीकृत अनुरोध किसी भी कनेक्शन के बनने से पहले विफल हो जाता है, और संदेश बताता है कि क्यों: `ऑफ़लाइन मोड: https://openrouter.ai
स्थानीय एंडपॉइंट नहीं है`। स्थानीय एंडपॉइंट से किसी और होस्ट पर रीडायरेक्ट भी अस्वीकार होता है। मोड चालू रहने के दौरान साइडबार के हेडर में एक छोटा **ऑफ़लाइन** बैज दिखता है। सेटिंग सहेजी जाती है। `--offline` / `ROOFTOP_OFFLINE=1` सेटिंग्स से स्वतंत्र रूप से मोड चालू करते हैं, और सेटिंग्स उसे बंद नहीं कर सकतीं।

#### "स्थानीय" का मतलब {#local-means}

`localhost`, लूपबैक (`127.0.0.0/8`, `::1`), निजी नेटवर्क के पते (`10/8`, `172.16/12`, `192.168/16`, `fc00::/7`), लिंक-लोकल पते, और `*.local` और `*.internal` नाम (जैसे `host.docker.internal`)। आपके घरेलू नेटवर्क के किसी दूसरे कंप्यूटर पर चलने वाला मॉडल स्थानीय माना जाता है, क्योंकि वह आपके नेटवर्क से बाहर नहीं जाता। नामों का मूल्यांकन उनके लिखे रूप से होता है, उन्हें खोजा नहीं जाता।

### ऑफ़लाइन मोड क्या जाँच नहीं सकता

* **stdio MCP सर्वर** आपके कंप्यूटर के प्रोग्राम हैं। iRoof.top उन्हें शुरू करता है, लेकिन यह नहीं देख सकता कि वे किससे जुड़ते हैं, इसलिए केवल वही जोड़ें जिन पर आपको भरोसा है कि वे स्थानीय रहेंगे।
* **आवाज़ का ट्रांसक्रिप्शन** Whisper `/audio/transcriptions` API के बजाय चैट API (एक `input_audio` भाग) का उपयोग करता है। इसके लिए एक स्थानीय सर्वर और मॉडल चाहिए जो वहाँ ऑडियो स्वीकार करे। अगर आपका नहीं करता, तो वॉइस संदेश फिर भी सहेजा और भेजा जाता है; केवल उसका टेक्स्ट नहीं होता।
* **छवि और आवाज़ का निर्माण** केवल [MCP टूल्स](../features/mcp) के रूप में मौजूद है। ऑफ़लाइन, इसके लिए एक स्थानीय MCP सर्वर का उपयोग करें।
* जिन लोगों के साथ आप साझा करते हैं, वे अपने ब्राउज़र में आपके Wi‑Fi लिंक खोलते हैं। ऑफ़लाइन मोड इस ऐप को नियंत्रित करता है, उनके डिवाइस को नहीं।

## दोस्तों के साथ सुरक्षित रूप से साझा करें {#share-with-friends-safely}

| लिंक | क्या होता है |
|---|---|
| **Wi‑Fi** `http://<आपका IP>:8737/s/<नाम>` | आपके स्थानीय नेटवर्क से कभी बाहर नहीं जाता |
| **इंटरनेट** `https://<नाम>.iroof.top/s/<नाम>` | ऐप हब के लिए एक आउटगोइंग WebSocket कनेक्शन खोलता है, जिसके ज़रिए हब विज़िटर के HTTP अनुरोध और आपके ऐप के जवाब आगे भेजता है |

इंटरनेट लिंक के साथ भी आपका एक्सपोर्ट, चैट और मॉडल आपके कंप्यूटर पर रहते हैं, और हब उनमें से कुछ भी नहीं सहेजता। हब केवल एक खाता रिकॉर्ड रखता है: आपका नाम, आपके सीक्रेट का हैश, और उसने आपको आख़िरी बार कब देखा।

यह *क्या नहीं* देता, इस बारे में स्पष्ट रहें। हब TLS समाप्त करता है, इसलिए किसी भी रिवर्स प्रॉक्सी की तरह, तकनीकी रूप से वह उससे गुज़रने वाला ट्रैफ़िक देख सकता है: विज़िटर जो टाइप करता है, पर्सोना के जवाब, और वह इतिहास जिसे लिंक विज़िटर्स को पढ़ने देता है (**विज़िटर एक्सपोर्ट पढ़ सकते हैं**, डिफ़ॉल्ट **कुछ नहीं**)। यह केवल विज़िटर पेज (`/s/…`, `/api/s/…`, पेज एसेट्स) आगे भेजता है और दोनों दिशाओं में कुकीज़ हटा देता है; आपका मालिक इंटरफ़ेस और सेटिंग्स इसके ज़रिए कभी उपलब्ध नहीं होते। अगर इतना भरोसा भी ज़्यादा लगे, तो Wi‑Fi लिंक इस्तेमाल करें, या [अपना रिले हब चलाएँ](../reference/relay-hub)।
[शेयर लिंक के बारे में और](../features/share-links)।

**ऑफ़लाइन मोड** में iroof.top रिले बंद है। Wi‑Fi लिंक काम करते रहते हैं।

## Telegram बॉट {#the-telegram-bot}

[Telegram से जवाब दें](../features/telegram) आपके ग्रुप में यह पोस्ट करता है:

* नए **विज़िटर संदेश** (नाम, लिंक का नाम, टेक्स्ट, या वर्णन या ट्रांसक्रिप्ट के साथ मीडिया लेबल, और जिस संदेश का वे जवाब दे रहे हैं उसका छोटा पूर्वावलोकन) और AI के **जवाब**;
* कभी भी एक्सपोर्ट किया हुआ इतिहास नहीं। पुराने संदेश नहीं भेजे जाते।

बॉट में एंड-टू-एंड एन्क्रिप्शन नहीं है: टेक्स्ट Telegram से सादे रूप में गुज़रता है। **साझा बॉट** के साथ यह हब से भी गुज़रता है, जो केवल यह रखता है कि कौन सा ग्रुप किस खाते का है। **अपना बॉट** हब के बिना सीधे Telegram से बात करता है। ऑफ़लाइन मोड दोनों को बंद करता है।

## आपका डेटा कहाँ जाता है

| डेटा | कहाँ जाता है |
|---|---|
| एक्सपोर्ट, चैट, सेटिंग्स, API कुंजी | आपके कंप्यूटर पर डेटा फ़ोल्डर |
| इम्पोर्ट और स्टाइल प्रोफ़ाइल | कहीं नहीं |
| इतिहास, स्टाइल प्रोफ़ाइल, आपके संदेश | आपके चुने हुए मॉडल एंडपॉइंट पर, हर जवाब में |
| फ़ोटो और आवाज़ | मीडिया मॉडल एंडपॉइंट पर, **वर्णन करें** पर या जब आप वॉइस संदेश रिकॉर्ड करते हैं |
| Wi‑Fi लिंक पर विज़िटर संदेश | आपका कंप्यूटर और आपका मॉडल एंडपॉइंट |
| इंटरनेट लिंक पर विज़िटर संदेश | हब (रास्ते में), आपका कंप्यूटर, आपका मॉडल एंडपॉइंट |
| Telegram के ज़रिए विज़िटर संदेश | अतिरिक्त रूप से Telegram, और साझा बॉट के लिए हब |
| ऑफ़लाइन मोड | केवल स्थानीय मॉडल एंडपॉइंट, केवल Wi‑Fi लिंक, कोई Telegram नहीं |
