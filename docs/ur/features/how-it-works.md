# یہ کیسے کام کرتا ہے

<div class="wide">

![iRoof.top کیسے کام کرتا ہے](/how-it-works.svg)

</div>

ہر ایکسپورٹ ایک جیسے معیاری پیغامات بن جاتی ہے۔ پھر شخص کا ہر عمل ماڈل کو **ٹول کال** کے طور پر دوبارہ دکھایا جاتا ہے، تاکہ وہ صرف یہ نہ سیکھے کہ وہ کیا لکھتا ہے بلکہ یہ بھی سیکھے کہ وہ *کیسے* بات چیت کرتا ہے، اور اسی طرح جواب دے۔

## عمل بطور ٹول کال

| کردار نے کیا کیا | تاریخ میں اور براہ راست جوابات میں ٹول کال |
|---|---|
| متنی پیغام، شاید جواب یا جزوی اقتباس کے ساتھ | `send_message {text, reply_to?, quote?}` |
| اسٹیکر | `send_sticker {sticker_id, reply_to?}` |
| لائبریری سے GIF، یا MCP ٹول سے URL | `send_gif {gif_id \| url, caption?}` |
| تصویر، ویڈیو، صوتی، آڈیو، فائل | `send_media {media_id, caption?}` |
| فارورڈ کیا ہوا پیغام | `forward_message {message_id}` |
| ری ایکشن | `react {message_id, emoji}` |
| *(پرانی تاریخ یاد کرنا)* | `search_history {query}` |

ایک نوبت میں کئی کالز کئی بلبلے بن جاتی ہیں۔ دوسری طرف کے پیغامات مختصر سطروں میں بدل جاتے ہیں، جن میں آئی ڈیز کا حوالہ ہوتا ہے:

```text
#52108 19:08 ↩ reply to #52107 (your: "grandmas lasagna 🍝"): You have made lasagna exactly zero times.
<sticker stk_156dbb381a>: a cat in a chef's hat, stirring a pot
reacted 😂 to #52107 ("grandmas lasagna 🍝")
```

## سسٹم پرامپٹ

| حصہ | |
|---|---|
| کون بننا ہے | کردار کی معلومات اور انداز کا اندازہ لگائیں، اور اس سے زیادہ نہ جانیں جتنا وہ جانتا ہو |
| انداز کا پروفائل | *پوری* ایکسپورٹ سے: پیغام کی لمبائی، بڑے حروف، علامات، ایموجی اور اسٹیکر کا استعمال، جواب اور ری ایکشن کی عادات، ایک نوبت میں بلبلے، لفظ بہ لفظ نمونے |
| لائبریری | اسٹیکرز، GIFs اور میڈیا، اور ان کا استعمال |
| نوٹس | وہ باتیں جو آپ نے اس شخص کے بارے میں لکھیں |

ایک چیٹ کے لیے پرامپٹ **ساکن** ہے: نہ گھڑی، نہ گنتیاں۔ ماڈل وقت `— day —` کے وقفوں اور `HH:MM` کی مہروں سے پڑھتا ہے، اور ہر درخواست اگلی کا بالکل ویسا ہی شروع ہے، اس لیے فراہم کنندگان کا prompt cache ہٹ ہوتا رہتا ہے۔

## طویل چیٹس {#long-chats}

```
 تاریخ کا بجٹ ───────────────────────────────────────────────▶
 ┌──────────────────────┬────────────────────────────────────────┐
 │ یادداشت (≤ 350 الفاظ)│ تازہ ترین نوبتیں، بجٹ کے 60% تک کٹی ہوئی│
 └──────────────────────┴────────────────────────────────────────┘
   تعلق، حقائق،            کٹنے کا مقام کافی دیر تک وہیں رہتا ہے،
   موضوعات، چلتے مذاق     تو cache شدہ حصہ بھی برقرار رہتا ہے
```

جب دوبارہ چلائی جانے والی تاریخ بجٹ سے بڑھ جائے، تو اگلا جواب پہلے سب سے پرانی نوبتوں (اور پچھلی یادداشت) کو ایک مختصر خلاصے میں سمیٹ دیتا ہے۔ درآمد پر یا چیٹ کھولنے پر کچھ خرچ نہیں ہوتا۔ انداز کا پروفائل پھر بھی پوری ایکسپورٹ سے آتا ہے، اور `search_history` ہر پرانے پیغام تک پہنچتا ہے۔ ٹوکن کا `usage` (prompt، cached، completion) `{ }` میں دکھایا جاتا ہے۔

## میڈیا لائبریری

چیٹ ماڈل متن پڑھتا ہے، اس لیے جب تک اسٹیکر کی تفصیل نہ ہو وہ صرف `<sticker stk_…>` ہے۔ **Describe with AI** گمشدہ آئٹمز کی تصاویر میڈیا ماڈل کو بھیجتا ہے، جسے vision سپورٹ کرنا ضروری ہے۔

* GIFs، ویڈیو اسٹیکرز اور ویڈیوز **ترتیب سے 4 فریمز** کے طور پر جاتے ہیں، تاکہ ماڈل حرکت دیکھ سکے۔ اس کے لیے [ffmpeg](https://ffmpeg.org) درکار ہے (`brew install ffmpeg`، `apt install ffmpeg`، `winget install ffmpeg`)، ورنہ تھمب نیل استعمال ہوتا ہے۔
* **Redo** ایک آئٹم کی تفصیل دوبارہ بناتا ہے۔ کوئی بھی تفصیل ہاتھ سے بدلی جا سکتی ہے۔
* تفصیلات ایکسپورٹ سے تعلق رکھتی ہیں اور اس کی تمام چیٹس کے کام آتی ہیں۔

[CLI](../reference/cli) سے خود دیکھیں: `rooftop convert <export> --persona "Jonas Weber"`۔
